CoreID · 项目结构说明

CoreID 项目结构与功能模块文档

这份文档面向项目维护者、接手开发者和接入方，用来快速理解 CoreID 仓库里每个目录、每个核心模块负责什么，以及它们之间如何协作。 重点不是逐行解释源码，而是从“业务能力”和“系统职责”角度说明项目结构。

项目类型：Node.js + Express + PostgreSQL 后台形式：单页 Admin HTML 身份底座：Casdoor 文档生成时间：2026-05-18

1. 项目总览

CoreID 是一个“统一身份 + 应用资格 + 套餐订单 + 安装包 + 落地页 + 后台管理”的综合平台。 它不是单纯的登录服务，而是把多个应用的用户中心能力统一到一个项目里。

统一身份

底层用 Casdoor 管理账号，CoreID 负责同步用户资料并提供应用接入接口。

核心能力

应用隔离资格

同一个身份不等于自动拥有所有应用资格，CoreID 用 membership 控制用户能进哪个应用。

核心能力

套餐与购买

平台配置套餐，应用读套餐、创建订单、确认支付，最终由 CoreID 统一维护权益。

核心能力

运营后台

管理员通过单页后台管理用户、订单、应用、安装包、落地页、套餐和审计日志。

核心能力

分发能力

支持安装包上传、下载统计、二维码下载，以及落地页草稿、发布、版本回滚。

核心能力

接入文档

项目内置 Android / Web 接入文档与 Markdown 导出能力，用于其他应用接入。

3. 运行入口

文件 作用 你通常什么时候看它
src/app.js 应用真正的启动入口，负责挂载 API、静态页、安全响应头、限流和错误处理中间件。 想知道系统“是怎么跑起来的”，优先看这里。
package.json 定义启动命令、依赖和项目名。 想确认用什么命令启动、有哪些核心依赖时看这里。
src/config/db.js 封装 PostgreSQL 连接池，是所有数据访问的基础。 数据库连接异常、环境变量或 SQL 调用问题时看这里。

4. 路由模块

路由层负责把外部请求分配到对应的业务模块。可以把它理解成“API 入口地图”。

文件 负责的功能 典型场景
src/routes/auth.js 后台管理员登录、Casdoor OIDC 跳转、回调、管理员会话验证。 管理员无法登录后台、Casdoor 跳转异常。
src/routes/identity.js 应用接入侧身份能力：发送验证码、注册、密码登录、单设备校验、当前用户、资格校验、自助改密码。 其他应用要接入手机号注册登录时最重要的模块。
src/routes/purchase.js 套餐列表、购买预校验、创建订单、订单查询、支付确认、当前权益。 套餐购买闭环、付费权益异常、支付联调。
src/routes/admin.js 后台主业务：用户管理、订单、应用管理、套餐配置、审计日志、SDK 文档导出。 后台页面大部分数据和操作都从这里来。
src/routes/release.js 安装包后台管理、版本历史、删除/回滚、下载统计、二维码，以及公开下载。 APK/EXE/DMG/Web/App Store 分发。
src/routes/landing.js 落地页上传、草稿预览、发布、历史版本、回滚，以及公开访问 /get/:slug。 运营落地页、下载页和页面版本控制。

5. 服务模块

服务层是项目的业务中枢，路由只负责接收请求，核心逻辑多半沉在这里。

5.1 身份与会话

casdoor.js

Casdoor OIDC 集成、issuer 兼容、JWT 校验、授权 URL 构建。

casdoorIdentity.js

Casdoor 用户创建、密码登录、后台更新用户、自助改密码底层能力。

session.js

后台管理员 Session token 与 Cookie 配置。

identitySession.js

应用接入侧的 identity token，包含 app_id 和 device_id。

userSync.js

把 Casdoor 用户资料同步到本地 users 表。

devVerificationCode.js

开发环境假验证码实现，当前默认固定码为 123456。

5.2 订单、套餐与支付

purchaseLifecycle.js

定义订单状态枚举和合法流转规则，例如 pending -> paid。

paymentCallback.js

支付回调签名校验，目前基于 HMAC-SHA256。

purchaseEventLog.js

记录订单生命周期事件，例如创建、确认支付、退款、状态变更。

5.3 分发与运营内容

landingDraft.js

生成默认落地页草稿模板，负责草稿文件目录和初始 HTML。

landingPage.js

渲染公开落地页，自动注入下载按钮和二维码。

qrcode.js

把下载链接或落地页链接生成为二维码 Data URL。

5.4 文档、日志与基础设施

sdkDocs.js

按应用类型动态生成 Android / Web 接入文档，并支持 Markdown 导出。

auditLog.js

记录后台管理员操作日志，例如上传安装包、回滚落地页、改订单状态。

userEventLog.js

记录用户级事件，例如注册、登录、改密码、设备顶替、资格变更。

bootstrap.js

运行时自动补齐数据库表和字段，避免迁移未执行时系统直接起不来。

7. 数据与初始化

db/init/001_schema.sql

数据库主结构。里面定义用户、订单、应用、套餐、安装包、落地页、日志、设备、membership 等核心表。

db/init/002_seed.sql

初始种子数据，例如默认应用、演示数据或后台初始展示所需的基础记录。

src/uploads/

本地文件存储区。安装包和落地页草稿/发布快照都落在这里。

主要业务表可以这样理解

  • users：统一用户资料的本地镜像。
  • user_app_memberships：用户是否拥有某个应用的注册资格。
  • devices：单设备登录规则依赖的设备记录表。
  • applications：平台上的应用清单。
  • app_plans：每个应用的套餐配置。
  • purchases：订单与购买记录。
  • app_releases / app_release_versions：当前安装包和历史版本。
  • landing_pages / landing_page_versions：落地页当前状态与历史版本。
  • operation_logs：后台管理员审计日志。
  • user_events / purchase_events：用户事件流与订单事件流。

9. 核心业务流

9.1 应用接入注册登录流

  • 接入方调用 /api/identity/send-code 发送验证码。
  • 调用 /api/identity/register 创建统一账号并开通某个 app_id 的资格。
  • 调用 /api/identity/login/password 登录，CoreID 返回 identity token。
  • 调用 /api/identity/me 和 /api/identity/access-check 验证当前会话与应用资格。
  • 需要改密码时调用 /api/identity/change-password。

9.2 套餐购买流

  • 后台在套餐配置里维护可售套餐。
  • 应用通过 /api/purchase/plans 拉取套餐。
  • 先调用 /api/purchase/preview 判断是新购还是续费。
  • 调用 /api/purchase/create 创建订单。
  • 支付成功后走 /api/purchase/confirm，CoreID 更新权益。
  • 接入方通过 /api/purchase/current-plan 同步当前权益。

9.3 安装包分发流

  • 后台上传二进制安装包或 Web / App Store 链接。
  • CoreID 维护当前版本与历史版本。
  • 用户通过 /download/:app_id/:type 或二维码下载。
  • 系统记录下载日志，用于统计和二维码追踪。

9.4 落地页运营流

  • 先创建落地页草稿，再上传正式 HTML。
  • 草稿预览与线上发布隔离，避免未发布内容污染线上页。
  • 发布后生成版本快照，可历史回滚。
  • 公开访问地址为 /get/:slug。

10. 阅读建议

想看整体先读：README.md + src/app.js 想接入登录：src/routes/identity.js + docs/*-integration.md 想看后台：public/admin/index.html + src/routes/admin.js 想看购买链：src/routes/purchase.js 想看分发：src/routes/release.js + src/routes/landing.js

维护建议：后续每新增一个大模块，最好同步把它的职责写进这份文档，避免项目继续扩张后只剩“文件越来越多，但没人知道各自干什么”。
