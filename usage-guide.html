1. 系统是做什么的

CoreID 不是单一登录页，而是一个统一用户中心平台。它把多个应用的身份、套餐、订单、安装包、落地页和后台运营能力收在一起。

统一身份

用户注册、登录、改密码、设备控制都走统一体系，底层身份由 Casdoor 管理。

应用资格

同一个用户可以只拥有某个应用的资格，不自动拥有全部应用登录权限。

套餐与订单

平台统一配置套餐，应用读取套餐并在购买成功后由 CoreID 更新权益。

内容分发

负责安装包上传、版本管理、下载统计、二维码下载，以及落地页发布。

2. 本地怎么进入系统

1

启动 CoreID 服务

当前本地开发推荐直接运行 Node 服务。通常启动后访问 http://localhost:3000。

2

确保 Casdoor 已运行

管理员后台登录、用户注册登录都会依赖本地 Casdoor，例如 http://localhost:8000。

3

打开后台入口

浏览器访问 http://localhost:3000/admin，使用 Casdoor 管理员身份登录后台。

4

打开测试页面

如果要测试应用侧注册/登录，不进后台，直接访问 /auth/register-test 和 /auth/login-test。

4. 统一身份怎么用

4.1 用户注册

1

选择目标应用

注册时必须带 app_id，因为注册的不只是账号，还包含“开通哪个应用资格”。

2

发送验证码

调用 POST /api/identity/send-code。开发环境默认验证码是 123456。

3

完成注册

调用 POST /api/identity/register，CoreID 会创建统一身份并写入该应用的注册资格。

4.2 用户登录

  • 当前主链路是 手机号 + 密码 登录。
  • 登录时必须带 app_id、device_id、device_name。
  • 如果用户没有该应用资格，会被拦截，不能登录别的应用。
  • 当前启用了“同一应用只允许 1 台有效设备”的规则，新设备登录会顶掉旧设备。

4.3 改密码

  • 用户自助改密码接口：POST /api/identity/change-password
  • 需要当前登录会话 + 原密码 + 新密码
  • 底层会调用 Casdoor 官方改密接口

5. 套餐与购买怎么用

5.1 平台管理员怎么配套餐

  • 进入后台 套餐配置 模块。
  • 选择应用，点击 + 新建套餐。
  • 填写套餐编码、名称、价格、时长、是否试用、是否可续费。
  • 保存后，应用就能通过接口读取到这个套餐。

5.2 应用怎么读套餐

  • 调用 GET /api/purchase/plans?app_id=... 获取当前应用可售套餐。
  • 应用侧只负责展示套餐，不负责定义套餐规则。

5.3 用户购买流程

1

先预校验

调用 POST /api/purchase/preview，判断当前是新购、续费，还是不允许购买。

2

创建订单

调用 POST /api/purchase/create，CoreID 会写入本地订单记录。

3

支付成功后确认

调用 POST /api/purchase/confirm，CoreID 更新订单状态和当前权益。

4

查询当前权益

调用 GET /api/purchase/current-plan，同步用户当前套餐和到期时间。

说明：当前已有本地业务闭环，但真实支付渠道仍需接入方继续对接。

6. 安装包管理怎么用

你可以做什么

  • 上传 APK / EXE / DMG 文件
  • 配置 Web / App Store 外链版本
  • 查看当前版本和历史版本
  • 回滚到旧版本
  • 只删当前版本，或删除整个历史
  • 查看下载统计
  • 生成下载二维码，扫码直接触发下载

典型操作

1

上传版本

在安装包管理页选择应用与平台，填写版本号后上传文件或链接。

2

查看历史版本

每个平台都可以打开历史面板，查看回滚或删除历史版本。

3

查看二维码

当前版本和历史版本都能生成二维码，扫码直接访问下载地址。

7. 落地页管理怎么用

核心特点

  • 草稿和线上页隔离，上传草稿不会直接覆盖线上内容。
  • 可以先预览草稿，再正式发布。
  • 发布会生成版本快照，支持回滚。
  • 支持默认模板生成、上传自定义 HTML、公开访问 /get/:slug。

推荐操作顺序

1

新建落地页

通过 + 新建落地页 为某个应用生成默认草稿。

2

上传或修改草稿

上传正式 HTML 或继续基于默认模板调整内容。

3

预览草稿

确认下载按钮、二维码和页面内容都正确。

4

发布上线

发布后公开地址才会切换到新内容。

8. 应用管理怎么用

  • 可以在后台新建应用，维护名称、描述、类型、状态。
  • 可以直接从应用卡片跳到该应用的用户、落地页、安装包上下文。
  • 可以查看并导出 SDK 文档。
  • SDK 文档会按应用类型输出 Android 或 Web 接入说明。

接入新应用的基本顺序

1

创建应用

在应用管理里点 + 接入新应用，填写基础信息。

2

配置套餐

为该应用补套餐，否则应用侧拿不到可售套餐。

3

配置安装包或落地页

如果应用有下载或投放场景，继续配置安装包和落地页。

4

导出 SDK 文档

给接入方导出 Markdown 文档，减少对接误差。

9. 接入测试怎么做

注册测试页

  • 地址：/auth/register-test
  • 用途：模拟手机号注册某个应用
  • 适合验证：验证码、注册资格、首次身份创建

登录测试页

  • 地址：/auth/login-test
  • 用途：模拟密码登录、设备切换、改密码
  • 适合验证：单设备顶号、当前用户接口、自助改密码

推荐联调顺序

  1. 先在后台创建应用
  2. 再在后台配置套餐
  3. 用注册测试页完成注册
  4. 用登录测试页完成登录
  5. 调用购买接口完成本地购买闭环
  6. 在后台用户管理和订单管理确认数据是否同步

10. 常见问题

问题 说明
一个用户能不能登录多个应用？ 可以，但前提是该用户分别拥有这些应用的注册资格。
一个应用里能不能多设备同时登录？ 当前默认不行，同一应用下只保留 1 台有效设备，新设备会顶掉旧设备。
应用买套餐是不是必须跳 CoreID 页面？ 不一定。当前推荐是应用自己做购买页面，CoreID 负责套餐、订单和权益中枢。
current-plan 是否需要 token？ 当前更适合服务端同步场景，后端可直接按 user_id + app_id 调用。
试用套餐和可续费字段是否完全生效？ 基础规则已经接上，但更复杂的支付、退款、提醒类闭环仍可继续补强。
