CoreID 服务器运维手册

涵盖 CoreID、Casdoor、PostgreSQL 的部署、更新、备份、SSL 续期和故障排查。

系统架构

CoreID 由三个 Docker 容器组成，通过 coreid-net 网络通信。外部流量通过助教云的 zjy_nginx 容器反向代理进来。

用户浏览器
    │
    ▼
zjy_nginx (443/80)
    ├── id.haoai.ink   → coreid-app:3000    (CoreID 应用)
    └── auth.haoai.ink → coreid-casdoor:8000 (Casdoor 认证)
                              │
                       coreid-postgres:5432  (PostgreSQL 数据库)
CoreID 应用
Node.js 20 + Express
认证服务
Casdoor (casbin/casdoor:latest)
数据库
PostgreSQL 16 Alpine
反向代理
zjy_nginx (共享)

查看服务状态

查看所有容器状态

cd /opt/coreid
docker compose -f docker-compose.prod.yml ps

正常状态下三个容器都应该是 Up，且 postgres 显示 (healthy)：

NAME              STATUS
coreid-postgres   Up (healthy)
coreid-casdoor    Up
coreid-app        Up

快速健康检查

# CoreID 健康检查
curl -s https://id.haoai.ink/health

# Casdoor 健康检查
curl -s https://auth.haoai.ink/api/health

# 数据库连通性
docker exec coreid-postgres pg_isready -U coreid -d coreid

查看资源占用

docker stats --no-stream coreid-app coreid-casdoor coreid-postgres

查看日志

查看各服务日志

# CoreID 应用日志（最近 100 行）
docker logs coreid-app --tail 100

# Casdoor 日志
docker logs coreid-casdoor --tail 100

# PostgreSQL 日志
docker logs coreid-postgres --tail 100

# 实时跟踪日志
docker logs coreid-app -f

筛选错误日志

# 只看错误
docker logs coreid-app --tail 200 2>&1 | grep -i "error\|fail"

# 看完整错误堆栈
docker logs coreid-app --tail 200 2>&1 | grep -A 15 "Error:"

重启服务

重启单个服务

cd /opt/coreid

# 重启 CoreID 应用（不重新读取 env 文件）
docker compose -f docker-compose.prod.yml restart app

# 重启 Casdoor
docker compose -f docker-compose.prod.yml restart casdoor

# 重启数据库（谨慎操作，会断开所有连接）
docker compose -f docker-compose.prod.yml restart postgres
restart vs up -d 的区别：restart 只是重启容器进程，不会重新读取 .env.production 文件。如果修改了环境变量，必须用 up -d。

重启所有服务

cd /opt/coreid
docker compose -f docker-compose.prod.yml restart

停止所有服务

cd /opt/coreid
docker compose -f docker-compose.prod.yml down
docker compose down 会停止并删除容器，但不会删除 volume 数据。
绝对不要加 -v 参数，否则数据库数据会被永久删除。

通过 Git 更新代码

推荐方式。前提：服务器上的 /opt/coreid 已经初始化为 git 仓库。

首次设置 Git（如果还没做）

在服务器上初始化并关联远程仓库：

cd /opt/coreid
git init
git remote add origin 你的仓库地址
git fetch origin
git reset --hard origin/main

日常更新流程

本地完成开发并推送到远程仓库：

# 本地操作
git add .
git commit -m "更新说明"
git push origin main

SSH 登录服务器，拉取最新代码：

ssh root@38.76.166.42
cd /opt/coreid
git pull origin main

重新构建并启动 CoreID 应用：

docker compose -f docker-compose.prod.yml up -d --build app

--build 参数会重新构建 Docker 镜像（安装新依赖、拷贝新代码）。

验证更新成功：

# 检查容器状态
docker compose -f docker-compose.prod.yml ps

# 检查日志没有报错
docker logs coreid-app --tail 20

# 健康检查
curl -s https://id.haoai.ink/health
如果只改了 .env.production 而没改代码，不需要 --build，直接 up -d app 即可。

通过 SCP 更新代码

适用于没有 Git 的场景，或者临时紧急修复。

在本地终端上传代码（注意是本地终端，不是 SSH 会话）：

scp -r /本地项目路径/* root@38.76.166.42:/opt/coreid/
注意排除 node_modules、.env.production 等文件，避免覆盖服务器配置。建议上传前先备份。

SSH 登录服务器，重新构建：

ssh root@38.76.166.42
cd /opt/coreid
docker compose -f docker-compose.prod.yml up -d --build app

更新环境变量

编辑环境变量文件：

vi /opt/coreid/.env.production

vi 基本操作：i 进入编辑 → 修改内容 → Esc 退出编辑 → :wq 保存退出 → :q! 不保存退出

重建容器使变量生效（必须用 up -d，不能用 restart）：

cd /opt/coreid
docker compose -f docker-compose.prod.yml up -d app

如果容器没有重建（显示 Running 而非 Started），加上 --force-recreate：

docker compose -f docker-compose.prod.yml up -d --force-recreate app

验证环境变量已生效：

docker exec coreid-app env | grep 你要检查的变量名

更新 Casdoor

Casdoor 使用官方 Docker 镜像，更新时拉取最新版本：

拉取最新镜像：

docker pull casbin/casdoor:latest

重建 Casdoor 容器：

cd /opt/coreid
docker compose -f docker-compose.prod.yml up -d casdoor

验证 Casdoor 正常：

curl -s https://auth.haoai.ink/api/health
Casdoor 大版本更新可能包含数据库 schema 变更，更新前建议先备份数据库。

备份数据库

手动备份

# 备份 CoreID 数据库
docker exec coreid-postgres pg_dump -U coreid coreid > ~/backups/coreid_$(date +%Y%m%d_%H%M%S).sql

# 备份 Casdoor 数据库
docker exec coreid-postgres pg_dump -U coreid casdoor > ~/backups/casdoor_$(date +%Y%m%d_%H%M%S).sql

# 备份所有数据库
docker exec coreid-postgres pg_dumpall -U coreid > ~/backups/all_$(date +%Y%m%d_%H%M%S).sql
备份前确保目录存在：mkdir -p ~/backups

设置定时自动备份

# 创建备份脚本
cat > ~/backup-coreid.sh <<'EOF'
#!/bin/bash
BACKUP_DIR=~/backups
KEEP_DAYS=30

mkdir -p $BACKUP_DIR

# 备份
docker exec coreid-postgres pg_dump -U coreid coreid > $BACKUP_DIR/coreid_$(date +%Y%m%d_%H%M%S).sql
docker exec coreid-postgres pg_dump -U coreid casdoor > $BACKUP_DIR/casdoor_$(date +%Y%m%d_%H%M%S).sql

# 清理旧备份
find $BACKUP_DIR -name "*.sql" -mtime +$KEEP_DAYS -delete

echo "[$(date)] Backup completed" >> $BACKUP_DIR/backup.log
EOF

chmod +x ~/backup-coreid.sh

# 添加 crontab，每天凌晨 3 点自动备份
(crontab -l 2>/dev/null; echo "0 3 * * * ~/backup-coreid.sh") | crontab -

验证备份

# 查看最新备份
ls -lht ~/backups/ | head -5

# 检查备份文件大小（不应该是 0）
du -h ~/backups/*.sql | tail -5

恢复数据库

恢复操作会覆盖现有数据，操作前请确认备份文件正确。

停止 CoreID 和 Casdoor（避免写入冲突）：

cd /opt/coreid
docker compose -f docker-compose.prod.yml stop app casdoor

恢复数据库：

# 恢复 CoreID 数据库
cat ~/backups/coreid_备份时间.sql | docker exec -i coreid-postgres psql -U coreid -d coreid

# 恢复 Casdoor 数据库
cat ~/backups/casdoor_备份时间.sql | docker exec -i coreid-postgres psql -U coreid -d casdoor

重新启动所有服务：

docker compose -f docker-compose.prod.yml up -d

数据库迁移

CoreID 没有使用自动迁移工具，schema 变更需要手动执行 SQL。

# 执行迁移 SQL
docker exec -i coreid-postgres psql -U coreid -d coreid <<'EOF'
-- 你的迁移 SQL
ALTER TABLE users ADD COLUMN new_field VARCHAR(100);
EOF
生产环境执行 SQL 前，务必先在测试环境验证，并备份数据库。

查看证书状态

# 查看证书到期时间
docker exec zjy_nginx openssl x509 -in /etc/letsencrypt/live/id.haoai.ink/fullchain.pem -noout -dates

# 或者在线检查
echo | openssl s_client -servername id.haoai.ink -connect id.haoai.ink:443 2>/dev/null | openssl x509 -noout -dates

Let's Encrypt 证书有效期 90 天，建议在到期前 30 天续期。

手动续期

执行续期命令（certbot 在助教云的 Docker 环境中运行）：

docker run --rm \
  -v /etc/letsencrypt:/etc/letsencrypt \
  -v /var/lib/letsencrypt:/var/lib/letsencrypt \
  -v /var/www/certbot:/var/www/certbot \
  certbot/certbot renew

重新加载 nginx 使新证书生效：

docker exec zjy_nginx nginx -s reload

自动续期

# 添加 crontab，每月 1 号和 15 号凌晨 4 点自动续期
(crontab -l 2>/dev/null; echo "0 4 1,15 * * docker run --rm -v /etc/letsencrypt:/etc/letsencrypt -v /var/lib/letsencrypt:/var/lib/letsencrypt -v /var/www/certbot:/var/www/certbot certbot/certbot renew --quiet && docker exec zjy_nginx nginx -s reload") | crontab -
可以用 crontab -l 查看已设置的定时任务。

502 网关错误

浏览器显示 502 说明 nginx 无法连接到后端容器。

排查步骤

  1. 检查容器是否在运行：

    docker compose -f docker-compose.prod.yml ps

    如果容器挂了，查看日志找原因：docker logs coreid-app --tail 50

  2. 检查 zjy_nginx 是否连接了 coreid-net 网络：

    docker network inspect coreid-net | grep zjy_nginx

    如果没有，重新连接：

    docker network connect coreid-net zjy_nginx
docker exec zjy_nginx nginx -s reload

  3. 检查 nginx 配置是否正确：

    docker exec zjy_nginx nginx -t

Casdoor 相关错误

"password or code is incorrect"

CoreID 使用管理员账号调用 Casdoor API，如果管理员密码配置不匹配会报此错误。

# 检查容器里实际使用的密码
docker exec coreid-app env | grep CASDOOR_DEV_ADMIN_PASSWORD

# 测试密码是否正确
curl -s "https://auth.haoai.ink/api/get-account?username=built-in/admin&password=密码" | head -c 200

如果返回不是 "status":"ok"，说明密码不匹配。修改 .env.production 中的 CASDOOR_DEV_ADMIN_PASSWORD 后重建容器。

"Casdoor is not configured yet"

# 检查 Casdoor 相关环境变量
docker exec coreid-app env | grep CASDOOR

确认以下值正确：

  • CASDOOR_ENDPOINT=https://auth.haoai.ink（给浏览器跳转用，公网地址）
  • CASDOOR_INTERNAL_ENDPOINT=http://coreid-casdoor:8000（容器间通信）
  • CASDOOR_CLIENT_ID 和 CASDOOR_CLIENT_SECRET 必须与 Casdoor 管理后台中的应用配置一致
  • CASDOOR_REDIRECT_URI=https://id.haoai.ink/api/auth/callback（不能是 localhost）

"Invalid client_id"

检查 .env.production 中的 CASDOOR_CLIENT_ID 是否与 Casdoor 管理后台中应用的 Client ID 一致。打开 https://auth.haoai.ink → Applications → 对应应用查看。

数据库连接失败

# 检查 PostgreSQL 是否健康
docker exec coreid-postgres pg_isready -U coreid -d coreid

# 检查 PostgreSQL 日志
docker logs coreid-postgres --tail 50

# 手动测试连接
docker exec -it coreid-postgres psql -U coreid -d coreid -c "SELECT 1;"

环境变量不生效

这是最常见的坑。修改 .env.production 后必须用 up -d 重建容器，restart 不会重新读取环境变量。

# 错误 ❌：restart 不会重新读取 env 文件
docker compose -f docker-compose.prod.yml restart app

# 正确 ✅：up -d 会检测变更并重建容器
docker compose -f docker-compose.prod.yml up -d app

# 如果 up -d 显示 Running（没有重建），强制重建
docker compose -f docker-compose.prod.yml up -d --force-recreate app

# 验证环境变量
docker exec coreid-app env | grep 变量名

清理测试用户

测试阶段清除用户需要同时清 CoreID 数据库和 Casdoor 两侧。

清 CoreID 数据库：

docker exec coreid-postgres psql -U coreid -d coreid -c "
DELETE FROM devices WHERE user_id IN (SELECT id FROM users WHERE phone = '手机号');
DELETE FROM user_app_memberships WHERE user_id IN (SELECT id FROM users WHERE phone = '手机号');
DELETE FROM verification_codes WHERE phone = '手机号';
DELETE FROM users WHERE phone = '手机号';
"

清 Casdoor 用户：打开 https://auth.haoai.ink → 管理员登录 → Users → 找到对应用户 → 删除。

以上 SQL 是分号分隔的多条语句，如果中间某条报错（如表不存在），后面的语句不会执行。此时需要单独执行剩余语句。
